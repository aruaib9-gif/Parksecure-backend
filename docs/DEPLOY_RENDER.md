# Deploying the ParkSecure API to Render

The repo ships with a [render.yaml](../render.yaml) blueprint that creates both the API web
service and its PostgreSQL database in one step.

## 1. Push the repo to GitHub

```bash
cd parksecure-main
git init && git add -A

# Confirm no secrets are staged — this must print nothing:
git diff --cached --name-only | grep -E '\.keystore$|keystore\.properties|(^|/)\.env$'

git commit -m "ParkSecure"
gh repo create parksecure --private --source=. --push   # or push to any remote
```

The `.gitignore` files already exclude `server/.env`, the release keystore and its passwords.
Run the check above anyway before your first push — a signing key committed once stays in the
git history even after deletion.

## 2. Create the Blueprint

1. Go to <https://dashboard.render.com> → **New +** → **Blueprint**.
2. Connect the GitHub repo. Render reads `render.yaml` and shows two resources:
   `parksecure-api` (web service) and `parksecure-db` (PostgreSQL).
3. Before applying, fill in the env vars marked `sync: false`:
   - `ADMIN_EMAIL` / `ADMIN_PASSWORD` — the initial super admin account (created by the seed step on first boot).
   - `SMTP_HOST` / `SMTP_USER` / `SMTP_PASS` — optional, required for exit-approval and invite emails.
     Any SMTP provider works (Resend, Mailgun, SES, Gmail app password).
   - `PAYSTACK_SECRET_KEY` — optional, required for card payments (NGN).
   - `PLATE_RECOGNIZER_TOKEN` — optional, enables AI plate recognition.
4. Click **Apply**. First deploy runs `prisma migrate deploy` automatically.

## 3. After the first deploy

1. Copy the service URL Render assigned (e.g. `https://parksecure-api-xxxx.onrender.com`) and update the
   **`APP_BASE_URL`** env var to match, then redeploy. This URL is embedded in email approval links
   and uploaded file URLs, so it must be correct.
2. Verify:
   - `GET https://<your-url>/health` → `{"status":"ok"}`
   - `https://<your-url>/api-docs` → Swagger UI
3. Log in as the super admin (`POST /api/auth/login`) or straight from the mobile app.

## 4. Point the mobile app at the API

Build the APK with your Render URL as the compiled-in default (see [BUILD_APK.md](BUILD_APK.md)):

```bash
cd mobile
PARKSECURE_API_URL=https://parksecure-api-xxxx.onrender.com npx expo prebuild --platform android --no-install
(cd android && ./gradlew assembleRelease)
```

If you named the Render service `parksecure-api` exactly as in the blueprint, the built-in
default (`https://parksecure-api.onrender.com`) already matches and no rebuild is needed.
Either way, testers can retarget an installed app from the login screen via
**Tap to change server**.

## 5. Paystack webhook (if using card payments)

In the Paystack dashboard set the webhook URL to:

```
https://<your-url>/api/webhooks/paystack
```

The server verifies the `x-paystack-signature` HMAC on every event and marks the matching
Payment / UserBill / SubscriptionPayment as paid on `charge.success`.

## Notes for production

- **File uploads** (`/uploads`) are stored on the service's local disk, which is **ephemeral** on
  Render — files disappear on redeploy. For persistent vehicle/item photos attach a Render Disk
  (uncomment the `disk:` block in render.yaml, paid plans) or swap the storage layer for S3/Cloudinary.
- **Free plan** spins the service down after ~15 min idle; the first request then takes ~30 s. The
  `starter` plan avoids this and is recommended for real usage.
- **Cron**: overstay/guest-expiry/exit-timeout detection runs inside the web service via node-cron
  (hourly + 5-minute timeout sweep). No separate worker needed.
- **Migrations** run on every deploy via the build command — schema changes only require a `git push`.
- `JWT_SECRET` is auto-generated by Render on first apply and persists across deploys.
